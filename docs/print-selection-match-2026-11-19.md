# SP/SPPH print selection verification — 19 November 2026

Seven added regression cases reproduced gaps before this change: a structurally valid confirmation could identify a different document, signing mode, official or field; a manual response did not have to match the submitted IDs, visible labels or explanation; and native inputs remained editable while confirmation was pending. Payment-mode checking already existed and remains in place.

SP and SPPH now verify the returned document number, mode, valid amount, automatic readiness and official labels. Manual responses must match the captured signer/title IDs, labels and trimmed reason. Automatic responses cannot introduce manual IDs or a manual reason. SP also verifies the selected field and normalized field explanation, as well as the existing payment choice. SP sends the visible manual official labels to the existing policy, which rejects obsolete names or titles even if an alternate manual master's rename does not affect the automatic recommendation fingerprint. No backend modification or additional lookup is needed.

Changed fingerprints still require explicit review. SP's existing exception for learning the first portfolio mapping requires a boolean `mapping_saved: true` and an actual request to learn that mapping; a truthy string or an unsolicited mapping acknowledgment cannot bypass review. Legitimate learning and read-only confirmation remain covered. An unverifiable response leaves the popup and draft available and does not navigate to the document preview.

Native select/input/textarea controls are disabled while the captured selection is being checked. Each original disabled state is restored after settlement, including validation failure and response-body timeout. Existing duplicate-submit, mode/manager click guards, cancellation and escaped error handling remain. This is a per-popup guard, not an exactly-once transaction guarantee, and it does not replace server validation or permissions.

Validation: all **636 JavaScript tests** pass, with the final whitespace normalization also checked by **52 focused tests**. **71 relevant PHP tests / 636 assertions** pass for selection input, preview reliability, SP payment/signing/field policies, SPPH automatic/manual signing and batched master choices. Actual browser fixtures cover desktop/light and mobile/dark for both modules: fields lock while checking, mismatched manual acknowledgment blocks preview, drafts survive rejection/timeout, changed data requires reconfirmation, and closing cancels requests. The SP payment browser scenarios pass both modes on both viewports, preserving one context read plus one combined choice read and one explicit confirmation POST. The lifecycle fixture declares UTF-8 and supports testing downloaded published scripts.

Production checks use array cache/session, prevented external HTTP and a read-only SQL transaction. Synthetic request/context objects validate the real active master IDs/labels without creating records, generating documents or changing user data. They verify normalized acknowledgment and obsolete-label rejection; selection validation uses the existing budget of SP auto/manual 1/2 queries and SPPH auto/manual 0/1 queries (this measures policy validation only, not the complete context request). Authentication/department guards are checked. Candidate and deployed probes must report completion and zero SQL writes.

Deployment is restricted to these two client scripts, their three test files and this document, from the exact previous commit. Private backups include the changed application files, bootstrap cache and both public scripts. Each public script is installed atomically and checked by HTTPS SHA-256, followed by health/authentication checks and browser fixtures using downloaded published assets. No schema, route, dependency, polling, backend query or global cache change is introduced. This batch improves print correctness and prevents conflicting in-flight input; it does not claim a measured site-wide speedup or an absence of all website bugs.
