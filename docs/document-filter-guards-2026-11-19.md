# SP/SPPH document filter guards — 19 November 2026

The document lists validated only search text while export validated additional filters. Lists could therefore reach database work with malformed PIC/vendor/date values; both actions accepted reversed date ranges. PHP truthiness also treated a PIC or SPPH vendor equal to `"0"` as no filter, returning broader results than requested. Filter chips had the same issue for search, PIC and vendor.

`ProcurementDocumentFilters::read` now provides one set of list/export rules before reference-cache reads, search queries or streaming. It validates nullable string PIC/vendor values of at most 255 characters, strict calendar dates, and chronological date ranges. Null values normalize to an empty string; `"0"` stays a real value. The existing document search validation remains in place. This changes filtering only: valid old years and open-ended ranges remain available, and save-time unusual-date confirmation is untouched.

Both controllers apply PIC/vendor constraints using explicit empty-string checks. The SP aggregate and result list use the same filtered base query, and exports retain their original filters, projections, CSV safety and bounded 200-document keyset batches. Blade chips and the initial filtered-state flag also use explicit empty-string checks, allowing a zero-valued search/PIC/vendor to be seen and cleared. No new automatic search, request, query or client dependency is added.

The SP statistics cache namespace changes from `goods-v2` to `goods-v3`. Old cached totals may have ignored PIC `"0"`; they must not be reused with the corrected row query. A regression test seeds an incorrect old entry, verifies fresh matching totals and confirms the old entry is not globally deleted. Existing 90-second expiry and mutation-version invalidation remain; no global cache flush is needed.

Six feature tests cover malformed filters before SQL, reversed ranges, literal zero PIC/vendor in lists and CSV, visible removable chips, matching SP totals, cache transition, inclusive/open-ended dates including 2025, Oracle mode, archived scope and read authorization. Four tests reproduced the initial faults before the fix; a separate old-cache regression failed before the cache namespace change. SQLite fixtures store date-only fields explicitly to match production DATE-column behavior rather than relying on SQLite to enforce that type.

The final full PHP suite passes **999 tests / 11,149 assertions**. The 19 existing JavaScript filter/action tests pass, including Apply, Export, Reset, clearing chips, date-range feedback, preserving Oracle/hologram context and blocking filter changes during secure deletion. Pint passes for the four changed PHP files. Fresh in-memory browser fixtures pass desktop/light and mobile/dark for SP/SPPH number lookup deadlines, cancellation, stale-response protection and escaped messages. Additional synthetic fixtures render the real zero-filter pages and verify visible chips, Export retaining `0`, clearing PIC while retaining the vendor, and Reset dropping the filters. Screenshots were inspected; no procurement mutation or native validation dialog occurred.

The read-only production baseline reproduced ignored zero filters for both lists and reversed ranges reaching SQL. Valid sampled day/PIC filters retained their list membership and produced the expected 12 SP and 5 SPPH documents in their CSV samples. These are bounded audit samples, not a site-wide speed measurement. Candidate/deployed probes require valid-filter and CSV parity, corrected zero filters and SP totals, and zero SQL for malformed/reversed inputs. Exports are capped at twenty sampled documents and their parent reads retain `LIMIT 200` without OFFSET. Probe logs contain counts and checks, not document content or user names.

Deployment is restricted to two controllers, the shared helper, two views, the feature test and this document, from exact baseline `3fbd7cbf88662bcfa4f698985efeb619101df8ed`. Modified application files and bootstrap cache are backed up privately. PHP lint and staged checks precede publication; PSR-4 fallback is checked for the new class. The helper is checked out from the exact target before the controller fast-forward, using a flow verified in an isolated repository. Deployed checks, source hashes, health/authentication checks and a clean tracked tree follow. Probes use array cache/session, prevented external HTTP and an explicit read-only database transaction with zero writes. No schema migration, public asset, dependency update or global cache rebuild is introduced. This batch avoids invalid database work and incorrect filter results; it makes no claim that every website operation is instant or bug-free.
