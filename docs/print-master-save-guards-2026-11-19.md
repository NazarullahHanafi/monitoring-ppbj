# Print master save guards — 19 November 2026

Two regression tests reproduced problems in the SP/SPPH print-master manager: a structurally valid response with a different name could clear the user's draft, and an edit rejected with HTTP 409 could immediately resend its obsolete version. List responses also lacked consistency/uniqueness checks, and a failed list read rendered the same no-matches text as a verified empty result.

Save acknowledgment now requires the submitted type, exact trimmed name and boolean active state, plus the edited ID when applicable and the existing typed/versioned row contract. Names are normalized before submission; drafts remain until the matching acknowledgment. Unverified responses remove obsolete row actions and block another write until a valid explicit read. That guard is tracked per master type, so loading titles cannot verify an uncertain signer write. Failed or malformed reads do not unlock it, switching types retains it, and closing an uncertain result carries it to the next opening in the same page runtime. There is no automatic POST retry or cross-page persistent draft storage.

A 409 removes obsolete row actions and marks the applicable edit stale. A successful list read does not silently replace that edit's fields or version. The user must explicitly select Edit on a freshly loaded row or cancel that edit. Fresh list reads also detect changed versions without waiting for a failed write. Stale flags and drafts survive type changes. Toggling the record currently being edited preserves the unrelated text correction and marks its old edit version stale when the version changes.

Manager lists must have unique typed rows, the requested bounded page, consistent total/last-page/row count and at most twelve rows. A verified page beyond the new last page is clamped once. Failed reads show an unavailable-list state; only verified empty results claim no matches. A confirmed save followed by a failed list refresh remains reported as saved. Departing during that follow-up read does not mark the confirmed write uncertain. Response error strings are bounded and escaped, internal traces are suppressed, and aborted late replies are checked before parsing or returning their data.

The full JavaScript suite passes **629 tests**. Backend checks relevant to the unchanged master contracts pass **24 PHP tests / 242 assertions**, covering master validation, version conflicts, access/delete protection and the combined choice read. Eight added JavaScript cases cover mismatched acknowledgment, obsolete edit resubmission, malformed pagination/duplicate rows, uncertainty scoped to the correct master type, stale versions across type changes, unavailable-versus-empty lists, confirmed/uncertain departure and toggling an edited record. Existing request deadlines, CSRF, draft preservation, read-only behavior, batched choices and cancellation coverage still pass.

Actual browser scenarios pass desktop/light and mobile/dark: conflicts require a fresh explicit Edit; stalled writes retain corrections; switching types or receiving a malformed list cannot lift the matching write guard; wrong save text is rejected; successful writes are distinguished from failed refreshes. Native validation dialogs and injected image elements do not appear. Viewport checks cover the stale and unverified states, with non-overlapping heading/content and a visible return action. Payment and SP/SPPH preview lifecycle browser checks also pass. Screenshots were inspected.

Deployment uses the exact prior commit and four-file allowlist, private application/bootstrap-cache/public-helper backup, staged/deployed read-only probes and atomic helper publication. Probes preserve array cache/session and read-only SQL transactions, verify the existing legacy/batched DTO/version/privacy/access contracts, manager page metadata and at-most-two-query page reads, and perform no real master or user changes. The previous optimization remains one combined choice request/SQL statement with at most fifty options per type. Controller/public asset hashes, unauthenticated access and health checks follow.

This batch changes only client behavior and tests/documentation. It adds no backend query, polling, schema, route, dependency or global cache flush. It avoids redundant failed writes and misleading feedback; it is not a site-wide latency or exactly-once guarantee. Backend uniqueness, permissions and version checks remain authoritative. A successful read allows the user to inspect an uncertain outcome and explicitly continue; drafts are retained only while the popup remains open.
