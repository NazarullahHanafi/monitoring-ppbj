# Dashboard dan keamanan penggantian password — 13 November 2026

Endpoint `/dashboard/data` sebelumnya menghitung ulang tujuh agregasi walaupun halaman dashboard sudah menyimpan data yang sama di cache. Sekarang HTML dan JSON memakai satu pemetaan cache dengan key/TTL lama yang sama. Respons JSON tetap privat; akses departemen dan hak refresh tetap diperiksa. Jenis data di luar kontrak dikembalikan sebagai validasi 422 sebelum query bisnis.

Filter workload buyer dinormalisasi menjadi mode dan batas tanggal. Parameter yang tidak mengubah periode tidak membuat entri baru. Pergantian hari/minggu menghasilkan key periode yang baru; key memasukkan versi aplikasi serta generasi invalidasi. Refresh mengganti satu generasi, menggantikan registry nama key yang terus tumbuh dan iterasi penghapusan tiap filter. Entri lama tetap kedaluwarsa dalam 60 detik. Registry deployment lama dibiarkan habis TTL; tidak ada flush cache menyeluruh.

Query periode menggunakan `tgl_ppbj >= awal` dan `< sehari setelah akhir`, tanpa fungsi SQL pada kolom tanggal. Ini menyertakan hari pertama untuk kolom DATE, seluruh hari terakhir, serta mendukung batas terbuka. Parameter tanggal, bulan, tahun dan mode divalidasi sebelum dipakai pada query atau Blade. Grafik enam bulan memakai tanggal satu sebagai acuan agar pengurangan bulan pada tanggal 31 tidak melewati Februari; query pengelompokan mendukung MariaDB/MySQL dan SQLite untuk pengujian.

Tombol refresh hanya terlihat bagi Superadmin Umum. Handler browser dikirim sebagai aset terpisah dengan versi filemtime: satu permintaan aktif, CSRF, batas waktu 20 detik, pemeriksaan status/JSON, pesan kegagalan inline, dan pemulihan tombol. HTTP 403/429 tidak menampilkan indikator berputar selamanya. Tidak ada retry otomatis dan reload hanya setelah konfirmasi sukses. Backend tetap memeriksa izin walaupun tombol disembunyikan.

Form penggantian password sebelumnya memakai `withInput()` ketika password lama salah, sehingga rahasia bisa masuk flash session. Sekarang pemeriksaan password lama menggunakan aturan `current_password` Laravel dan mekanisme pengecualian password dari old input. Bentuk array dan input terlalu panjang ditolak dengan 422. Batas bcrypt 72 byte diperiksa sebelum hashing, termasuk untuk karakter multibyte; kebijakan huruf besar/kecil/angka lama tetap dipertahankan. Hanya akun login yang disimpan. Endpoint diberi batas 5 percobaan per menit per akun, dengan prefix terpisah dari pembacaan dan refresh dashboard.

Pengujian mencakup cache HTML/API, registry, normalisasi, pergantian hari, tanggal pertama/terakhir, tahun kabisat, bulan/minggu/tahun dan batas terbuka, grafik akhir bulan, filter rusak, akses per role, budget terpisah, password tidak masuk session, percobaan lintas akun, dan input multibyte. Browser desktop serta sentuhan ponsel memverifikasi tombol sebenarnya; tes JavaScript memeriksa klik ganda, CSRF, timeout, pemulihan, dan respons ditolak.

Hasil lokal: suite PHP penuh 741 lulus dengan 7.190 assertion; suite JavaScript penuh 334 lulus; browser desktop dan sentuhan ponsel lulus; Pint pada kelima file PHP yang diubah/ditambah lulus. Hasil ini memverifikasi lingkup perbaikan dan regresi yang diuji, bukan jaminan seluruh sistem bebas bug atau kebal serangan.

Deploy tidak memerlukan migrasi, perubahan dependensi, atau perubahan data bisnis. Aset `dashboard-actions.js` harus diterbitkan ke webroot sebenarnya, lalu route/view di-cache ulang. Pemeriksaan hosting memakai transaksi baca saja, cache array terisolasi, dan identitas sintetis untuk validasi password. Tidak mengubah password pengguna atau mencoba kredensial akun produksi. Hasil kecepatan cache tidak mewakili seluruh latensi halaman atau jaringan.
