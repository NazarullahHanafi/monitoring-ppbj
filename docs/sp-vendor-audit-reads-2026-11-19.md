# SP vendor audit read reuse — 19 November 2026

The SP index already eager-loaded linked PRs for its ten displayed rows, but `buildSpVendorAuditMap` independently queried those PRs again to retrieve their SPPH references. The audit then queried the referenced SPPHs to produce the vendor status labels. A fully linked page therefore performed a redundant PR read on every refresh.

The existing PR eager projection now includes `spph_rfq_1`. The audit reuses loaded PR models only when that column is present, never triggering a lazy relation load. It issues one batched fallback PR query only for primary references absent from the loaded map. Documents with legacy scalar references or incomplete relation projections retain their lookup behavior. The map is restricted to primary references before collecting SPPH numbers, so secondary grouped PRs do not replace the primary audit or introduce extra vendor reads. `put` preserves numeric-looking map keys, and explicit nonempty filtering retains literal `0` PR/SPPH references previously dropped by truthiness checks.

Vendor matching, labels, normalization and active-SPPH scopes are unchanged for ordinary references. Only the vendor warning for literal zero references is deliberately corrected. There is no new business-state cache: a fresh page reads current PR/SPPH data, including raw SQL PR updates and SPPH deletion/restoration. The SQL predicates for the list, numbering modes, pagination, exports, writes and authorization are unchanged. No schema, public asset, JavaScript or view change is needed.

Six added feature tests cover a ten-SP linked page, match/mismatch/manual/no-SPPH/empty-vendor/deleted-SPPH states, mixed linked and legacy references, incomplete projections, primary-versus-secondary grouped PRs, literal zero references, empty pages, raw SQL updates, deletion/restoration and department/viewer access. The original implementation failed five cases. For a fully linked page, the audit decreases from **two queries to one**; loaded PRs without SPPHs need **zero** audit queries. A mixed/legacy page remains bounded by one fallback PR query plus one SPPH query. The focused set passes **38 tests / 332 assertions** and the full PHP suite passes **1,047 tests / 11,887 assertions**. Pint passes on the controller and new test file.

The initial read-only production comparison reproduces the repeated read: the current ten-row automatic-numbering page has nine distinct nonempty primary PR references, all already available through its loaded relations, yet uses two audit queries and eight total warm index queries. The candidate/deployed probes compare the exact previous controller from commit `05a031eac6842ae7b70cdb5cd15f1a4fe50c9d8e`, require equal pagination membership/order/count and vendor labels, and check that only absent primary references appear in fallback bindings. They also cover the Oracle index, which is empty in the initial sample, and a synthetic linked/legacy page using existing PR metadata without saving models. This measures query work for these paths; it is not a promised percentage improvement in whole-site latency.

Deployment is restricted to the SP controller, feature test and this document. Modified tracked files and bootstrap cache are backed up privately before a fast-forward. Candidate and deployed production probes run in a read-only SQL transaction, use array cache/session, prevent external HTTP, and report aggregate counts without document/vendor identifiers. They do not create, approve, modify, delete or print production documents. Source hashes, health/authentication responses and a clean tracked tree are checked after deployment. No migration, cache rebuild, asset publication or global cache flush is required.
