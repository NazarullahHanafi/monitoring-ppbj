# Master PPBJ: validasi, modal, dan pembaruan dropdown

Audit lanjutan dari baseline `38e08f7`. Lingkupnya master Buyer, Portofolio, Metode Pengadaan, dan Penyedia Eksternal yang dibuka dari Management PPBJ. Menu Satuan dan fitur lain tidak diubah pada putaran ini.

Pemeriksaan metadata production mengonfirmasi kolom nama Buyer/Metode Pengadaan berukuran varchar(50), sedangkan Portofolio/Penyedia Eksternal varchar(100). Validasi lama menerima 100 untuk semuanya, sehingga nama sepanjang 51–100 karakter dapat lolos validasi lalu gagal di database. Batas backend sekarang sesuai kolom, teks di-trim sebelum validasi, dan konfigurasi batas yang sama dikirim ke modal. Nama kosong/array/terlalu panjang mendapat 422 tanpa write.

Controller menghapus wrapper izin yang tidak diperlukan, metode izin yang tidak dipakai, serta penghapusan cache yang berulang. Listener model di AppServiceProvider tetap menjadi sumber invalidasi cache dropdown dan cache konsumen lama. Tes mengisi cache kemudian memastikan satu penghapusan per key untuk tambah/edit/hapus, beserta hasil dropdown yang segar. Cache baca 300 detik dan projection id/nama tetap dipertahankan. Respons mutasi juga private/no-store.

Master CRUD diekstrak dari ppbj.js menjadi master-data.js berversi filemtime, tanpa dependensi baru. Kode lama tidak lagi mendefinisikan handler yang sama. Rendering daftar menggunakan elemen DOM, nilai input, dan teks; nama tidak dipasang sebagai HTML. Dropdown dibangun menggunakan Option dengan nilai asli, memperbaiki double escaping pada nama yang mengandung ampersand/kutip. Pilihan yang sedang diubah ikut nama baru; pilihan lain dan nilai formulir yang tidak tercantum dalam master dipertahankan. Penghapusan hanya mengosongkan pilihan yang memang dihapus dan tidak lagi tersedia.

Pembacaan memiliki AbortController dan identitas operasi. Respons/error jenis master lama tidak boleh mengubah jenis baru atau panel yang sudah ditutup. Satu penjaga mutasi mengunci pergantian/penutupan panel dan pengiriman berulang, termasuk saat konfirmasi hapus. Jenis master dan ID ditangkap sebelum request. Timeout 30 detik mencakup body JSON; sesi/izin/validasi/throttle ditangani dengan informasi inline. Timeout/network/5xx diberi status belum terkonfirmasi dan tidak diulang otomatis. Kegagalan mempertahankan input di panel; pembatalan memulihkan kontrol. Pagehide membatalkan operasi dan invalidasi identitas mencegah kelanjutan lama mengirim/mengubah UI setelah pemulihan halaman.

Setelah konfirmasi penyimpanan, daftar/dropdown diperbarui dari respons server. Edit/hapus tidak lagi menjalankan GET tambahan untuk membangun ulang dropdown. Tampilan Select2 yang sudah ada disinkronkan melalui change tanpa timer reinitialization tambahan. Konfirmasi menggunakan teks biasa pada SweetAlert/FormUX; keberhasilan menggunakan toast sukses yang sesuai.

Endpoint baca/tambah/edit/hapus memakai prefix throttle terpisah: 60/20/20/10 per menit. Batas mutasi lama dipertahankan. Parameter ID nonnumerik, nol, atau melebihi rentang integer ditolak sebagai 404, menghindari error coercion pada argument controller. Hak Superadmin Umum untuk master umum serta hak user Umum non-viewer pada Penyedia Eksternal dan middleware read-only tetap berlaku.

Validasi lokal: 791 tes PHP / 8.418 assertion dan 363 tes JavaScript lulus. Setelah guard ID besar ditambahkan, 18 tes fitur terkait / 372 assertion diulang dan lulus. Pint pada tiga berkas PHP, parser dua aset JavaScript, serta git diff --check lulus. Browser desktop dan ponsel memakai markup modal/aset asli untuk menguji respons lama, klik ganda, tipe request yang benar, CSRF, kegagalan validasi, nama literal, rename pilihan aktif, pembatalan hapus, dan tidak ada GET setelah write. Browser catatan PPBJ juga diulang dan lulus setelah ekstraksi.

Verifikasi hosting memakai cache array terisolasi dan transaksi database read-only untuk memeriksa schema, batas validasi, query dingin satu/hangat nol, payload, dan limiter sebelum fast-forward. Tidak ada master production yang ditambah, diedit, atau dihapus untuk pengujian. Deploy menyiapkan backup dan memublikasikan dependency baru sebelum halaman merujuknya, lalu memeriksa checksum kedua aset dan status HTTP.

Pembatasan: penjaga mutasi berlaku per halaman; tidak menambahkan uniqueness atau version lock antar-tab/user. Snapshot lokal setelah write tidak menyinkronkan perubahan user lain secara real time. Data lama yang sudah tersimpan tidak dipotong atau dimigrasikan. Hasil pengujian ini bukan jaminan seluruh website bebas bug atau kerentanan.
