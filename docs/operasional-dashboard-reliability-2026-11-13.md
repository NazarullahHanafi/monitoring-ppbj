# Dashboard Operasional — 13 November 2026

Pekerjaan dilanjutkan pada 16 November 2026. Pengujian fitur PHP, JavaScript, dan browser desktop/ponsel diulang dan lulus sebelum penerapan; baseline production masih `be7c3b5` tanpa perubahan tracked lokal.

Statistik lama memeriksa keberadaan seluruh riwayat PENDING/APPROVED/REJECTED untuk setiap TOR/PR. PR yang pernah ditolak lalu diajukan ulang bisa terhitung di beberapa kategori sekaligus; KPI juga merata-ratakan permintaan pending lama yang sudah selesai. Sekarang status berdasarkan approval dengan ID terakhir, dengan fallback received_at hanya bila tidak ada status approval yang dikenal. Aturan ini sama dengan daftar PR terbaru. Tidak ada perubahan keputusan approval atau data TOR/PR.

Statistik dan KPI digabung dalam satu agregasi melalui latest receipt. Durasi pending memakai clock aplikasi sebagai parameter SQL, dengan waktu negatif dibatasi nol. Snapshot, grafik enam bulan, tiga PR terbaru, dan enam portofolio membutuhkan empat query sumber pada cache dingin. HTML dan JSON memakai cache yang sama; pembacaan hangat tidak menjalankan query bisnis. Key baru memakai namespace `ops-dashboard:v2`, agar cache berisi semantik lama tidak dipakai. TTL tetap: snapshot/portofolio lima menit, grafik sepuluh menit, daftar terbaru satu menit. Grafik membaca batas tanggal inklusif/eksklusif tanpa fungsi pada predicate kolom; pengelompokan mendukung MariaDB/MySQL dan SQLite. Pembersihan/refresh mencakup ranking portofolio dan tetap terbatas pada key dashboard ini.

Endpoint pembacaan, refresh, dan clear memakai prefix throttle terpisah dengan batas lama. Hanya Superadmin Operasional melihat tombol refresh; pemeriksaan hak backend dan mode read-only tetap berlaku. JSON bersifat private/no-store. Tidak ada cache global yang di-flush, migrasi, atau dependensi baru.

Refresh browser dipindahkan ke aset dengan versi filemtime. Permintaan pertama tetap ditunda 60 detik setelah render awal. Hanya satu pembacaan aktif, ada batas waktu 30 detik yang mencakup body JSON, respons diverifikasi sebelum diterapkan, dan data lama dipertahankan bila hasil tidak lengkap. Tab tersembunyi membatalkan pembacaan; pagehide membatalkan operasi dan mengabaikan hasil lama. Pageshow dari bfcache/visibilitychange melanjutkan tanpa menumpuk timer. Error otorisasi aktif menghentikan polling sampai reload; respons otorisasi dari operasi lama tidak mengubah state baru.

Refresh manual membatalkan pembacaan, memakai CSRF, mencegah klik ganda, tidak retry otomatis, dan baru reload setelah server mengonfirmasi. Timeout/kegagalan melepaskan tombol dan menampilkan status inline. Respons lama tidak boleh me-reload halaman yang sudah dipulihkan. Daftar kosong mengganti isi lama agar dokumen yang sudah tidak ada tidak tetap terlihat.

Nama portofolio, nomor PR, tujuan, tanggal, dan label status sebelumnya dimasukkan langsung ke innerHTML saat refresh. Nilai teks/atribut sekarang melalui escaping, dan struktur payload diperiksa sebelum callback renderer. Browser menguji string HTML berbahaya pada teks dan title, memastikan tidak muncul elemen/handler dari isi data. Tidak ada perubahan isi dokumen bisnis; escaping hanya pada presentasi.

Pengujian mencakup riwayat approval, received fallback, KPI pending aktif, batas tanggal/bulan kabisat, cache/query budget, ranking TORPR, izin dan throttle, klik ganda, timeout body, halaman dipulihkan, respons lama, injeksi HTML, serta pengosongan daftar. Verifikasi hosting memakai cache array terisolasi, transaksi baca saja, perhitungan pembanding dari riwayat approval, dan penanda selesai eksplisit sebelum maupun setelah deploy. Statistik yang terlihat tetap mengikuti TTL; polling bukan jaminan perubahan instan pada setiap detik.

Validasi lokal: 757 tes PHP lulus (7.960 assertion), 341 tes JavaScript lulus, browser desktop dan sentuhan ponsel lulus, serta Pint pada kedua file PHP perubahan/tes lulus. Pengujian browser memastikan payload HTML tidak menjadi elemen aktif, daftar lama dibersihkan ketika kosong, CSRF disertakan, klik ganda tidak menggandakan refresh, dan kontrol pulih setelah kegagalan. Hasil ini terbatas pada skenario yang diuji; tidak menjamin seluruh website bebas bug atau kerentanan.
