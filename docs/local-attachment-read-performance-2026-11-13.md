# Pembacaan metadata lampiran lokal dan unduhan — 13 November 2026

Daftar sumber OCR lampiran SP/SPPH sebelumnya mengambil seluruh baris lampiran, termasuk teks hasil ekstraksi/pemeriksaan, kemudian membaca dokumen, relasi PR, dan nomor PR ulang untuk setiap file. Satu batch 80 lampiran dapat membutuhkan sekitar 241 query. Sekarang query lampiran memproyeksikan tujuh kolom metadata saja, lalu dokumen, relasi PR, dan identitas PR dibaca per batch. Pengujian 80 dokumen berbeda pada masing-masing modul membutuhkan empat query, sama dengan satu dokumen. Teks OCR/review dan rincian barang tidak dihidrasi pada jalur manifest.

Nomor PR manual dan relasi pivot tetap digabung. Pencocokan identitas PR memakai equality di SQL. UNION hanya menggabungkan ID numerik: nomor manual dibandingkan dengan parameter terikat pada kolom PPBJ, sedangkan nomor pivot dibandingkan antar kolom PPBJ yang sama. Ini mengikuti collation kolom PPBJ tanpa menggabungkan kolom teks SP/SPPH yang collation-nya bisa berbeda. String metadata dan rumus versi sumber dipertahankan; tidak ada penghapusan hasil OCR, migrasi, atau reindex massal. Setiap batch membaca metadata terbaru tanpa menambahkan cache jangka panjang.

Ukuran batch dinormalisasi ke 1–100. Sebelumnya `has_more` dibandingkan dengan limit asli dari pemanggil, sehingga permintaan di atas 100 atau nol bisa mengakhiri pemindaian terlalu awal. Sekarang satu baris tambahan menentukan apakah masih ada halaman berikutnya. Baris tambahan tidak dikembalikan atau dilewati cursor; `last` selalu merujuk baris terakhir yang dikembalikan. Uji 135 file dengan ukuran default dan limit di atas maksimum memastikan setiap file terlewati sekali. Draft belum diklaim tetap dikecualikan; file hilang/dokumen terhapus tetap dikembalikan sebagai sumber tidak aktif untuk sinkronisasi.

Unduhan rincian lokal sekarang menggunakan lokasi kanonis dari `ProcurementLocalFiles`, menolak file di luar disk privat termasuk symlink yang keluar dari root. Respons memakai BinaryFileResponse agar HEAD dan permintaan byte-range didukung tanpa memuat seluruh file ke memori. Disposisi unduhan Unicode tetap ditangani framework. Hak baca draft, masa klaim, departemen, viewer, serta dokumen soft-delete dipertahankan. Respons unduhan dan preview lokal dari pencarian memanggil `setPrivate()` secara eksplisit karena constructor BinaryFileResponse dapat menetapkan public meskipun header awal menyebut private. Header no-store/nosniff dan sandbox preview tetap berlaku.

Tes baru meliputi batas query, proyeksi metadata, pagination, link PR pivot/manual, pembaruan metadata, fingerprint, sumber terhapus/hilang, batas ukuran dan checksum penyalinan, akses lintas akun, path traversal, HEAD/range, serta cache privat. Fixture file memakai direktori unik di `tmp`, terpisah dari lampiran pengguna. Verifikasi hosting menggunakan transaksi baca saja untuk manifest aktual dan fixture terisolasi untuk download/range/symlink. Tidak ada perubahan data bisnis atau percobaan mengakses file rahasia.

Validasi lokal: 750 tes PHP lulus (7.912 assertion), 334 tes JavaScript lulus, dan browser berhasil menguji upload, pembacaan PDF digital/scan, konfirmasi versi, serta tampilan ponsel tanpa overflow atau permintaan dokumen eksternal. Pint pada empat file PHP yang berubah/ditambahkan lulus. Angka empat query berlaku untuk metadata batch lokal, bukan seluruh waktu OCR atau unduhan OneDrive. Tidak ada jaminan mutlak seluruh website bebas bug atau seluruh scan pasti terbaca.

Pemeriksaan hosting menemukan collation tabel legacy berbeda. Varian awal UNION teks sudah diganti dengan UNION ID numerik; service sempat dipulihkan ke versi sebelumnya selama perbaikan. Verifier juga diperketat: exception harus menghasilkan exit nonzero dan deploy wajib menemukan penanda penyelesaian pemeriksaan, bukan hanya mengandalkan exit status PHP yang bisa ditangani exception handler framework.

Varian ID numerik lulus 50 tes terfokus (1.142 assertion) dan pemeriksaan kandidat di MariaDB hosting: empat query per modul, relasi/versi sumber cocok dengan pembacaan legacy, range 206, traversal/symlink 404, dan nol SQL bisnis yang ditulis. Tidak ada perubahan charset/collation tabel produksi.
